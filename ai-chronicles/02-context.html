AI 编年史 01：上下文 (Context) 的记忆战争

🔖本文约 1637 字，阅读预计耗时 5 分钟。
ⓘ本篇整体暂不由博主构思，而是由 Gemini 自主编写，博主负责学习和校验，注意甄别。[狗头]
2026年2月14日 ·AITech History·🏷️ Context Window🏷️ RAG🏷️ Long Context🏷️ Memory🏷️ Chronicle

0. 核心工程概念：Token 与 Embedding ​

在讨论“记忆”之前，必须先理解 AI 是如何“阅读”的。

0.1 Token：模型读的不是字 ​

Token 是分词算法在“压缩效率与表达能力”之间做的取舍结果。它可以是一个字、一个词，甚至是一个字节。

  • 工程后果：
    • 你的输入长度以 Token 计价（成本/延迟）。
    • “边界条件写得太长”会直接把上下文窗口撑爆。

0.2 Embedding：把离散符号变成向量 ​

文字、类目、ID 都是离散符号，计算机没法直接算。Embedding 做的事就是：把离散符号映射到一个向量空间里，让“相似性”有机会被学习出来。

  • 工程直觉：Embedding 是模型的“词典”，坏 Embedding 会让模型一开始就听不懂你在说什么。

第一阶段：前 Transformer 时代 —— 金鱼的记忆 (Pre-2017) ​

在 Transformer 出现之前，NLP 领域由 RNN (Recurrent Neural Networks) 及其变种 LSTM/GRU 统治。

1.1 背景与痛点 ​

  • 技术背景：RNN 是一种串行结构，像人类阅读一样，读一个字，更新一次内部状态 (Hidden State)。
  • 核心痛点：
    • 梯度消失 (Vanishing Gradient)：随着序列变长，早期的信息在反向传播中逐渐归零。
    • 无法并行：必须等上一个字处理完才能处理下一个，训练极慢。
    • 短视：RNN 很难记住 100 个词之前的内容，就像金鱼只有 7 秒记忆。

1.2 关键突破 ​

  • LSTM (1997)：通过引入“门控机制” (遗忘门、输入门)，强行让模型记住重要信息。虽然缓解了问题，但没根治。
  • Seq2Seq + Attention (2014)：Bahdanau Attention 首次提出“注意力机制”，让解码器在生成每个词时，都能回过头看一眼输入序列的所有词。这是 Context 概念的雏形。

第二阶段：Transformer 的诞生 —— 固定窗口的枷锁 (2017 - 2020) ​

Google 团队发表神作 Attention Is All You Need，彻底改变了格局。

2.1 背景与痛点 ​

  • 技术背景：Transformer 抛弃了循环，完全基于 Self-Attention。它能一次性看到所有词之间的关系。
  • 核心痛点：
    • O(N2)O(N^2)O(N2) 复杂度：Attention 矩阵的大小是序列长度的平方。如果序列长 2 倍，计算量增加 4 倍。这导致显存和算力无法承受长文本。
    • 位置编码限制：早期的绝对位置编码 (Absolute Positional Encoding) 训练时定死了最大长度 (如 512 或 1024)，推理时无法超越。

2.2 关键论文 ​

  • Attention Is All You Need (2017)：定义了标准 Transformer 架构，Context Window 通常限制在 512 tokens (BERT) 或 1024 tokens (GPT-1)。

第三阶段：GPT-3 与工程 Hack —— 带着镣铐跳舞 (2020 - 2023) ​

OpenAI 发布 GPT-3，虽然参数量巨大 (175B)，但 Context Window 依然只有 2048 tokens。

3.1 背景与痛点 ​

  • 业务问题：2048 tokens 大约只有 1500 个汉字。多轮对话没几句就超了，长文档根本读不完。
  • 工程范式 (Hack 方案)：既然模型不行，工程师就开始整活。
    • 滑动窗口 (Sliding Window)：只把最近的 N 轮对话塞进 Prompt，前面的直接截断。
    • 摘要缓冲 (Summary Memory)：让 LLM 定期总结之前的对话：“我们之前聊了 A、B、C...”，然后把摘要塞进 System Prompt。
    • Map-Reduce：处理长文档时，把文档切成 10 段，分别总结，最后再总结“总结的总结”。

3.2 代表产品/库 ​

  • LangChain：依靠封装各种 Memory 模式 (Buffer, Summary, KnowledgeGraph) 起家，本质上是在帮模型“外挂”记忆管理。

第四阶段：RAG 与向量数据库 —— 外挂海马体 (2023) ​

随着 ChatGPT 的爆火，企业知识库需求井喷。既然 Prompt 塞不下，那就“按需加载”。

4.1 背景与痛点 ​

  • 业务问题：模型有幻觉 (Hallucination)，且知识停留在训练截止日期。企业有大量私有 PDF/Wiki 需要问答。
  • 核心痛点：Fine-tuning 太贵且慢，无法实时更新知识。

4.2 解决方案：RAG (Retrieval-Augmented Generation) ​

  • 原理：
    1. Indexing：把海量文档切片 (Chunking)，用 Embedding 模型转成向量，存入向量数据库。
    2. Retrieval：用户提问时，搜出最相关的 Top-K 个片段。
    3. Generation：把片段拼接到 Prompt 里：“请根据以下资料回答...”。
  • 延伸问题：
    • 切片破碎：切片可能把一句话切断，导致上下文丢失。
    • 召回不准：关键词匹配不一定代表语义匹配。

4.3 关键技术与产品 ​

  • Vector DBs：Pinecone, Milvus, Chroma, Weaviate。
  • Embedding Models：OpenAI text-embedding-ada-002, BGE (BAAI)。

第五阶段：Long Context 大爆发 —— 暴力美学 (2023 下半年 - 2024) ​

模型架构师们终于出手了，通过算法优化打破了 O(N2)O(N^2)O(N2) 的魔咒。

5.1 背景与痛点 ​

  • 业务问题：RAG 只能回答“局部”问题，无法回答“全文总结”或“跨段落推理”的问题（大海捞针问题）。
  • 技术突破：
    • FlashAttention (Dao et al.)：通过显存 IO 优化，让 Attention 计算速度提升数倍，显存占用大幅降低。
    • RoPE (Rotary Positional Embedding)：旋转位置编码，支持外推 (Extrapolation)，让模型能处理比训练时更长的序列。
    • ALiBi：另一种位置编码，天然支持长文本。

5.2 代表产品 ​

  • Claude 2 (100k) -> Claude 3 (200k)：以“大海捞针”测试全绿著称。
  • Kimi (Moonshot AI)：支持 20万字，后续通过 Cache 机制支持 200万字。
  • Gemini 1.5 Pro (Google)：利用 Ring Attention 架构，支持 100万 ~ 1000万 Tokens。这是一个质变，可以直接把 1 小时的视频、几十本代码库塞进 Context。

第六阶段：无限未来 —— 结构化与系统 2 (Future) ​

当 Context 足够长时，注意力分散 (Lost in the Middle) 成了新问题。未来的方向不是单纯堆长度，而是“结构化”。

6.1 新的挑战 ​

  • 注意力稀释：给模型 100 本书，它可能反而变笨了，找不到重点。
  • 成本问题：输入 1M tokens 的费用极其昂贵。

6.2 演进方向 ​

  • GraphRAG：微软提出的概念。先用 LLM 把文档提取成知识图谱 (Knowledge Graph)，查询时在图上游走。这解决了 RAG “只见树木不见森林”的问题。
  • MemGPT / System 2：模拟操作系统的内存管理。
    • RAM (Context)：放当前最关注的信息。
    • Disk (VectorDB)：放冷数据。
    • Swap 机制：让 Agent 自己决定什么时候把信息写入磁盘，什么时候读出来。

6.3 总结 ​

从“金鱼记忆”到“外挂硬盘”，再到“超大内存”，AI 上下文的发展史，就是一部算力与算法协同进化的历史。
