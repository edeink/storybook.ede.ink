十年回望：从 WebOffice 到 Agent 的工具演进 ​

业务思考不够，期望是可以再技术 + 业务侧，能充当桥梁，虚线带几个人，一起干出成绩的。

背景：之前面试，被面试官点到在业务层思考不足，个人也认可当时确实在业务层的思考不足。但毕竟已经工作了十年，从 WebOffice 到 AIGC，我见证了工具从“离线”走向“云端”，再走向“智能”的全过程。这里整理了关于工具演进的思考。

1.0 时代：从文字（WebOffice Word） 到 文档（Notion-Like） ​

我的起点在金山，参与的第一款工具是 WebOffice 的 Word。当时我是一个典型的技术思维导向的研发，只想用 React 做复杂的 Web 应用。在 Word 项目中，我参与了个人简历、水印、光标选区、IME 预输入、iPad 适配等基础核心功能的开发。

现在回过头看，仅仅把 Office 搬到 Web 上是不够的。当时金山已经完成了从 PC 到 Mobile 的转型，移动端装机量早已超过 10 亿。如果 WebOffice 仅仅是为了“打开即用”或者为了技术重构，动用两三百人的团队是不划算的。当时的 产品，Yeppy（WebOffice 为个人带来了数千万收益的大佬，官至 P11 副总经理）给出的答案是：协作。说得玄幻一点叫“云原生”。

WebOffice 确实带有协作的使命，但 Word 的表现不如 Sheet。当时（2019年）Word 的日活（DAU）约为 30W，而 Sheet 已超 200W。这还没算上疫情期间 Sheet 因数据收集需求带来的爆发增长。为什么 Word 难做？因为 Word 本质上是排版软件，是面向打印机（A4纸）、面向线下分发的产物。

Word 上能体现“协作”的功能并不多：一个是修订与审阅（在云评论基础上的进阶模式，类似 Git 的 Commit/Accept/Reject），另一个是分享。这更多是 WebOffice 套件的通用能力，而非 Word 本身的突破。真正的互联网原生，讲究万物连接、随意分发与嵌套。因此，文档——一种 Notion-Like 的产品诞生了。它以 Block 为抽象，每个 Block 就像浏览器的 Tab，通过沙箱机制容纳不同内容，实现了 All in One。飞书文档现在日活也有三百多万日活，正是基于这种“Document 即 Workspace”的理念。我的好基友阿锦靠着这个产品晋升 P8，我也因攻克光标选区一致性难题拿到了绩效 A，沾了点光。

2.0 时代 到 2.5 时代的思考：2024 年在电商的 AIGC 探索 ​

时间跳跃到 2024 年 5 月，我在字节电商做了一个基于 模板（Template） 的生成链路：Figma -> Schema -> AIGC Render。站在 2025 年的视角看，它可能有点过时，但值得解构。

2.5 时代的尝试：结构化生成 ​

在指令编辑（Nano）尚未普及之前，主流还是基于 StableDiffusion。当时我的思路是在“纯底图”逻辑上做文章。Nano 的指令编辑（如“识别物体 -> Mask 擦除 -> Inpaint”）虽然灵活，但当时技术尚不成熟。我构建了一套基于**模板（Template）**的生成链路。本质上是在不确定的 AI 生成内容上，引入确定性的 Schema 约束。

痛点与局限 ​

这套技术链路虽然闭环，但约束太强：

  1. 数据扩充瓶颈：自定义 Schema 导致没有生态。虽然有 Figma 插件，但采购高质量 Figma 模版成本极高（一套 3000 RMB）。
  2. 多样性受限：为了避免 BadCase，我们在 Prompt 层面（基于 AB 测试）加入了“纯色背景”、“无装饰”等严苛词汇，导致 AIGC 变成了“背景颜色生成器”。

与之形成对比的是虚拟试衣。它没有使用 Schema 强约束，而是直接通过 Mask + OpenPose + 3D 粗模 + 扩散模型，达到了非常好的效果。这给了我很大启发。所以，就好像 Office Word 是 1.5 产品一样，我称我 24年做的东西，为 Agent 时代的 2.5 产品。

3.0 时代：2025 年与 Agent 元年 ​

2025 年是 Agent 元年，拥有理解能力的 LLM 开始重构工具链：

  • 字节内部：Anime 内容系统已推广至 CodeReview、文档生成、架构图编写等领域，成为年度 OKR编写 的常客。传统流程任务（如工单）逐渐被 LLM 接管，呈现 All in One 态势。
  • AI Coding：Trae 等工具贡献了我下半年 99.5% 的代码。AI Coding 本身就是面向垂直领域的 Agent Tool。
  • AIGC 领域：随着 Nano 落地、Sora 2.0 出台，指令式绘制进一步冲击传统 AIGC。
    • 案例：电商算法团队每天花费 2 万美金微调小模型，但研发团队通过“秘密专项”直接调用 Sora 2.0，效果更好。这说明技术（大模型）正在降维打击算法（小模型微调）。

3.1 架构演进：从 GUI 到 LUI (A2UI) ​

这是一个面向 B 端的尝试，核心是将 UI 抽象为 “数据（展示什么） + 动作（点击后做什么）”。

  • 新协议：Markdown / Natural Language。以前是基于 API 协议调用，现在是基于 Workflow + Prompt。
  • 黑盒与智能：在一个严谨的编码系统中，引入“黑盒”（模型），虽然引入了不确定性，但也引入了智能。
  • MultiAgent：大模型（高智商）负责编排，小模型（快速度）负责执行，多数公司做微调。

3.2 工具演变：从“工具链”到“对话流” ​

随着模型增强，很多交互变成了对话。

  • UI 变化：出现了专门的 AI UI 语言（如 Ant Design X），MDBox（可参考 GPT） 等适合 Token 流式输出的组件。
  • 交互形态：左侧是对话（如 Trae Solo 模式），右侧是辅助性的传统工具。
  • 工作流重构：不再是 Schema -> Editor -> Render，而是 Conversation -> Render Model -> Reverse Parsing（反向解析数据）。

在 3.0 时代，“协作”与“All in One”依然重要，但核心变成了集成 SOP 与 Skills。Agent 利用强理解力和动态规划能力作为“大脑”，传统功能点退化为 Workflow 中的节点。

而且，一般大公司在这方面更由于形成数据闭环，比如工具生产的链路，比如说是否采纳编辑图片，是否推送到商详或其它应用，都可以作为 RHLF 后训练的重要数据，减缓了数据标注的成本。（只有自闭环才算真正意义的 3.0，Agent 还只是 2.8）

Aha 狂想曲：工具 4.0 ​

如果说 3.0 是对话式工具，那么我永远有一个工具类的圣杯：4.0（也可能是 5.0）自举（Bootstrap）。

可以注意到，Agent 已经在模糊了终端的边界（典型的，就是最近大火的 Clow / Claude Computer Use，这种边界模糊，是不是会逐渐发展成 3.5？）。未来是否可以进一步模糊“物理”概念？素材源源不断地从生产线中来，回到生产线中去，通过商业智能扩充上下文，完成无人工干预的自我迭代。 目前和我的大学基友，林铖（港大博士、前腾讯高级研究员、前米哈游算法负责人，现澳科大副教授）展开了 在 AR/VR 层面 初步的合作。
